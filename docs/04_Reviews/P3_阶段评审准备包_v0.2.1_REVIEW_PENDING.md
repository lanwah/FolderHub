## 4. 架构结论摘要

### 4.1 已确认的架构决策

- ADR-034：每个交互式用户会话一个独立 CardHost。
- ADR-035：Main Process
  写业务主数据、GlobalSettings、CardDefinition；CardHost 写
  CardPresentationState。
- ADR-036：Main Process 与同会话 CardHost 使用 Windows Named Pipes。
- ADR-037：Main Process 已退出且 Keep=ON 时 CardHost 崩溃，不增加常驻
  Supervisor；下次 Main Process 启动时恢复最后成功持久化状态。
- ADR-038：Main Process 仍运行时 CardHost 崩溃，由 Main Process
  负责有限重启、退避和失败提示；具体参数未定。
- ADR-039：首版采用 SQLite 本地数据库；ADR-035 的逻辑聚合单一写入者规则不变。
- ADR-040：采用显示器身份 + 工作区归一化坐标 + DPI 换算；沿用 Q-026/ADR-033 的原显示器优先和主显示器可见区域回退行为。
- ADR-039：首版采用 SQLite 本地数据库；ADR-035 的逻辑聚合单一写入者规则不变。
- ADR-040：采用显示器身份 + 工作区归一化坐标 + DPI 换算；沿用 Q-026/ADR-033 的原显示器优先和主显示器可见区域回退行为。

这些决策只在各自记录范围内有效，不代表所有底层技术方案已选定。

### 4.2 尚属候选/假设的内容

- CardHost 持有 Named Pipe Server、Main Process 作为
  Client：`DESIGN_ASSUMPTION / NEEDS_VALIDATION`。
- WPF/Win32 Adapter 和运行时组合：候选，尚未批准。
- SQLite 已选定；配置格式、表结构、事务/原子提交、并发锁和迁移细节待 P4。
- 多显示器/DPI 策略已选定；显示器稳定身份字段、混合 DPI 和迁移算法细节待 P4。
- Named Pipes 的具体 API、DACL ACE、身份握手和 nonce 传递实现：未验证。
