本次仅形成审计报告并登记任务完成情况。未修改 RAW/Q/ADR/CR/RISK 的业务内容、SRS 需求内容、用户确认记录或任何基线。

## 3. 详细发现与建议

### F-01 模板索引未完全切换到 V2.6.1 独立模板（P2）

`docs/templates/README.md` 当前仍将：
- Open_Issues.md → 问题与决策台账模板.md
- Decision_Log.md → 问题与决策台账模板.md

映射到历史合并模板。实际资料库中已存在 `未决问题台账模板.md`、`决策台账模板.md`、`问题澄清记录台账模板.md`。建议修正文档映射；保留旧模板作为历史兼容，不删除。

### F-02 Q/CLQ 活动记录未实例化四维模型（P1）

Q-015、Q-026 当前仅保留历史影响分类与 Q 状态。CLQ-024 有问题背景、选项、推荐、置信度和未回答状态，但没有 D 等级、决策处理状态及四维状态记录。

建议下一次实际处理 Q-026 时：
- 暂定评估为 D2（重要用户体验/布局恢复规则），并记录判级依据；若进一步分析发现涉及核心架构/不可逆范围，再升级判级；
- 保留 Q-026 原 OPEN 状态，另设决策处理状态；
- 分别填写记录完整性、决策完成度、阶段阻塞性、延期有效性；
- 用户回答前不得把推荐 A 写入 SRS 正式需求或 ADR。

Q-015 属于 P3 技术架构事项。可先按 D2 候选进行评估；若架构影响达到系统总体架构或重大不可逆后果，应升级为 D1。其不应被误判为 P2 的当然阻塞项，但进入 P3 架构决策/基线前必须解决或有效延期。

### F-03 ADR-032 子项状态表达混合（P2）

ADR-032 内部各 Q 子项采用“CLOSED / CONFIRMED（RECONSTRUCTED）”。这实际包含：
- Q 当前状态；
- 用户确认状态；
- 历史证据等级。

建议通过追加说明或后续版本将其拆分为独立字段，不追溯性覆盖历史原文，不撤销已确认决策，也不提高 RECONSTRUCTED 证据等级。ADR-001～ADR-031 的历史 CONFIRMED 状态不要求因本次复核重新向用户确认。

### F-04 CR-001 缺少决策分级与处理状态（P2）

CR-001 将 Windows Server 支持范围扩展至 Server 2012+ GUI/Desktop Experience，属于实质性平台范围决策。建议按 D1 进行追溯性分类（依据：改变首版目标平台范围），并记录：
- 决策处理状态：已由用户确认（范围）；
- 变更/验证状态：兼容性逐版本验证待执行；
- 阶段影响：不阻断当前 P2 需求整理；P3/P4 必须执行兼容性验证；
- 关联 Q-016/Q-019/Q-020、ADR-022/025/026、RISK-001。

该分类不要求用户重复确认既有范围。RISK-001 的 ACCEPTED 状态及用户接受证据保持不变，接受风险不等于兼容性验证通过。

### F-05 SRS v0.8 缺少 AI 推导/设计假设来源标记（P1）

全文检索结果：
- `AI_DERIVED`：0 处；
- `DESIGN_ASSUMPTION`：0 处。

明确例子：第 4.1 节“本机交互式桌面用户”注明“由首版运行环境范围归纳”，属于推导性内容，但未标记来源、依据、适用范围、置信度/风险和验证方式。

建议新增独立“AI 推导与设计假设登记表”，对 SRS 中实际存在的推导内容逐项标记：
- 类型：AI_DERIVED / DESIGN_ASSUMPTION；
- 来源与依据；
- 适用范围；
- 置信度/风险；
- 影响；
- 验证/评审方式；
- 状态及关联需求。

不得将助手推导提升为用户原始需求或用户确认决策；D1 内容不得通过推导或默认值替代用户确认。

### F-06 SRS 未决项列表有状态错误和重复项（P2）

SRS 第 13.1 节把 Q-023 放在“已登记未决问题”表中，但 Open_Issues 中 Q-023 已 CLOSED / CONFIRMED。第 13.3 节“多显示器、DPI 或分辨率变化后的桌面组件位置恢复”重复列出。

建议仅修正 SRS 草案中的索引/清单，不修改 Q-023 的历史记录或用户确认内容。

### F-07 P2 阶段门禁判断（P1）

- Q-026：暂定 D2。它影响桌面组件位置恢复的用户可见行为，当前仍待用户确认。现有 CLQ-024 只是提出选项并等待回答，不构成有效延期。
- Q-015：P3 技术架构事项，不应自动阻断 P2；但延期记录还需明确责任方、影响、防护、触发条件和 P3 重审节点。
- CR-001：范围决策已由用户确认；兼容性验证属于后续验证义务，不应误判为 P2 用户决策未完成。
- RISK-001：用户接受剩余风险不代表兼容性验证通过；继续保留 P3/P4 验证要求。

结论：P2 可以继续处理不依赖 Q-026 的需求分析工作；但在 Q-026 解决或形成有效延期、SRS 推导/假设披露和质量检查完成前，不应提交 P2 APPROVED，不建立需求基线，也不得启动 P3。

### F-08 风险台账版本元数据（P3）

`Risk_Register.md` 的工作流规范标识仍为 V2.5.0。V2.6.1 保留 V2.5 三层风险机制，因此这不是风险规则失效；建议在后续管理文档修订时仅更新版本引用，不改变 RISK-001 的风险等级、ACCEPTED 状态或接受证据。
