# FolderHub CLQ-159：多显示器/DPI 位置持久化策略

- 澄清编号：CLQ-159
- 关联问题：Q-P3-DISPLAY-001
- 阶段：P3_HIGH_LEVEL_DESIGN
- 决策等级：D2
- 状态：CLOSED / CONFIRMED
- 证据等级：本轮用户回答 VERBATIM；本轮选项/权衡/推荐 DOCUMENTED
- 关联需求基线：REQ-BL-1.0（SRS v0.11）
- 关联设计：P3-04 v0.3、P3-09 v0.2
- 关联决策：ADR-033、ADR-040
- 日期：2026-11-21

## 1. 问题背景与影响

Q-026 / ADR-033 已确认恢复产品行为：尽量保持原显示器及相对位置；原显示器不可用或位置全部/部分移出可见桌面时，迁移至当前主显示器可见区域；主组件和独立卡片分别处理。本题只选择位置保存和坐标换算策略，不改变上述行为。

## 2. 提交用户选择的完整选项

| 选项 | 方案 | 优点 | 缺点/代价/风险 |
|---|---|---|---|
| A（推荐） | 显示器身份 + 工作区归一化坐标 + DPI 换算；保存显示器识别信息和相对工作区的位置比例，恢复时按当前工作区/分辨率/DPI 换算，显示器不可用时按 Q-026 迁移 | 对分辨率变化更有适应性；保留相对布局意图；能与 Q-026 的显示器恢复/主显示器回退行为衔接 | 显示器稳定身份标识、工作区计算、混合 DPI、旋转/拓扑变化、缩放舍入和多卡片冲突算法仍需 P4 细化；归一化坐标不保证像素级原位 |
| B | DIP 逻辑坐标；保存相对显示器的 DIP 偏移量，恢复时按 DPI 缩放 | 与 Windows UI 逻辑单位相对一致；对 DPI 缩放较直观 | 分辨率/工作区变化仍可能越界；不同 DPI awareness 模式和跨显示器移动需处理；不能单独解决显示器身份/拓扑变化 |
| C | 物理像素坐标；保存屏幕像素位置并直接恢复 | 简单直接；同分辨率/同拓扑下容易保持位置 | DPI、分辨率和任务栏工作区变化容易造成偏移或不可见；跨显示器恢复风险高 |
| D | 其他方案，由用户补充 | 可覆盖特殊显示器/桌面管理要求 | 需重新评估与 Q-026 行为一致性、DPI/拓扑变化和实现复杂度 |

## 3. 助手推荐

- 推荐：A（显示器身份 + 工作区归一化坐标 + DPI 换算）。
- 理由：最贴合 ADR-033 已确认的“原显示器及相对位置恢复”行为，并为显示器不可用、工作区变化及 DPI 缩放提供可计算的恢复输入；同时能按组件独立恢复。
- 推荐置信度：高（针对策略方向）；具体监视器标识字段、DPI awareness 和几何换算算法仍需 P4 定义与验证。
- 依据缺口：尚无目标多显示器/DPI 实机测试；RDP/Explorer/显示器热插拔行为未验证。

## 5. 最终确认结论

用户选择 A：采用“显示器身份 + 工作区归一化坐标 + DPI 换算”作为位置持久化与恢复策略。该策略必须实现 Q-026 / ADR-033 已确认的回退行为；主组件与每张独立卡片分别保存和恢复位置。

本选择不确定具体显示器 ID 算法、设备路径/EDID 字段、坐标原点、DPI awareness 模式、窗口边界可见性阈值、缩放舍入、工作区变化处理和多卡片碰撞布局；这些在 P4 详细设计。实机行为继续 `NEEDS_VALIDATION`。
