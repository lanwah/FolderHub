# CLQ-022：搜索匹配方式、大小写及触发行为

- 关联问题：Q-024
- 关联需求：RAW-001、RAW-003
- 关联决策：ADR-015、ADR-017、ADR-029
- 阶段：P2_REQUIREMENT_ANALYSIS
- 状态：CLOSED / CONFIRMED
- 记录版本：V1.1
- 创建日期：2026-11-12
- 来源：SRS v0.3 交互缺口复核；搜索范围已确认，但匹配细节尚未确认。

## 1. 问题与背景

已确认首版支持按文件夹真实名称和别名搜索，不提供高级筛选；别名允许重复。尚未确认搜索是部分匹配还是完整匹配、是否区分大小写、何时触发搜索，以及无结果时如何反馈。

本问题只补充搜索交互语义，不改变搜索范围、不增加高级筛选，也不决定具体搜索算法/索引技术。

## 2. 本轮选项

| 选项 | 完整含义 | 优点 | 缺点/代价/风险 |
|---|---|---|---|
| A（推荐） | 输入关键词后按真实名称和别名进行不区分大小写的包含匹配；输入变化时动态更新结果；清空关键词恢复当前分类完整列表；无结果时显示明确提示 | 符合常见桌面搜索习惯；用户不必输入完整名称；行为容易理解和验收 | 动态更新需避免大量记录时卡顿；不定义拼音/模糊匹配 |
| B | 仅完整匹配真实名称或别名；不区分大小写；按回车或点击搜索按钮后执行 | 结果精确，交互和实现简单 | 用户必须知道完整名称/别名，快速查找效率较低 |
| C | 包含匹配但区分大小写；输入变化时动态更新 | 能区分大小写不同的字符串 | Windows 文件名通常不依赖大小写区分，用户容易因大小写输入不同而找不到 |
| D（其他） | 用户自定义匹配、触发或反馈规则 | 可满足其他具体习惯 | 需要补充完整规则和边界 |

## 3. 助手推荐

**推荐：A（中高置信度）。**

依据：
- 用户已明确首版要提供名称/别名搜索，产品定位是快速访问。
- 包含匹配和动态更新能减少输入成本；不区分大小写更符合常见 Windows 使用预期。
- 无结果提示和清空恢复列表能形成完整交互闭环。

未知信息：用户是否希望仅在按回车后搜索、是否需要拼音/模糊匹配。推荐 A 不包含拼音、错别字容错或高级筛选；如需这些能力应另行提出。
