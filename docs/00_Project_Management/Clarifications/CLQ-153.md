## 1. 问题背景

ADR-034 已确认每个交互式用户会话使用一个独立 CardHost 进程承载该会话全部独立卡片；主应用可退出，CardHost 在全局保留开关开启时继续运行。NFR-002 要求每张卡片的位置和锁定状态跨应用重启保存。因此，主应用退出后，卡片仍可能发生拖动/锁定操作，相关状态不能依赖已经退出的主进程完成保存。

本问题只确定 Main Process 与 CardHost 对卡片数据的权威写入边界，不选择数据库、文件格式、IPC 技术、物理存储位置或加密技术；不改变 FR-016/017/019、NFR-002、BR-012 或 ADR-034。

## 2. 需要确认的问题

**Main Process 与 CardHost 之间，卡片定义和卡片展示状态的持久化写入权应如何划分？**

## 3. 选项版本 V1

### A. 按逻辑聚合划分单一写入者（推荐）

- Main Process 拥有分类、文件夹记录、分类关联、主组件配置、全局退出策略及卡片启停定义。
- CardHost 是每张卡片位置、锁定状态和显示环境恢复状态的唯一权威写入者；即使 Main Process 已退出，也可直接保存。
- 双方通过 IPC 传递卡片启停命令、元数据快照和状态变更事件；每个聚合带版本号，禁止旧快照覆盖较新卡片状态。
- 只确认逻辑写入权，不决定底层是否同一个数据库文件或分离存储。

优点：符合主程序退出后 CardHost 独立运行；字段/聚合单写者明确；业务主数据与窗口状态分离；不额外增加第三个常驻进程。

缺点/代价/风险：跨进程同步、版本对账和并发控制需要设计；卡片启停与文件夹删除涉及两个聚合，需要事务或补偿流程；物理后端必须支持目标 OS 和并发访问。

### B. CardHost 独立拥有完整卡片聚合

- CardHost 是 CardDefinition（卡片启停、关联文件夹）和 CardPresentationState（位置、锁定）的唯一权威写入者。
- Main Process 对卡片的增删改启停全部通过 IPC 请求 CardHost；文件夹业务主数据仍由 Main Process 管理，并向 CardHost 发送元数据快照。

优点：卡片定义与展示状态在一个进程/存储边界内；CardHost 独立运行时状态完全自主；卡片聚合内部事务边界更集中。

缺点/代价/风险：主程序的卡片管理依赖 CardHost 可用；文件夹删除、路径更新、别名/用途说明修改需要跨存储协调；主程序恢复时需进行更复杂的元数据对账和补偿。

### C. Main Process 独立拥有全部持久化数据

- Main Process 是卡片定义和展示状态的唯一写入者；CardHost 只把拖动/锁定等事件发送给 Main Process。
- 主程序退出后，CardHost 必须使用本地事件队列/日志暂存状态，待 Main Process 下次启动后回放。

优点：持久化写入口集中；数据一致性规则可集中实现。

缺点/代价/风险：主程序退出期间存在状态暂存窗口；本地队列损坏、重复回放、顺序错乱和冲突合并增加复杂度；不适合 CardHost 长时间独立运行的场景。

### D. 独立 Persistence Host / Service

- 新增第三个持久化宿主进程/服务，Main Process 和 CardHost 均通过 IPC 调用统一数据服务。

优点：集中事务、迁移、备份和访问控制；客户端无需直接竞争存储。

缺点/代价/风险：增加第三进程/服务的启动、权限、部署、升级和故障恢复复杂度；若采用 Windows Service，还需处理 Session 0 与用户会话隔离；目前没有足够证据证明其必要性。

### E. 其他

用户可提出其他写入权或数据所有权划分方式。

## 4. 助手推荐

- 推荐：A。
- 置信度：中高。
- 理由：ADR-034 明确要求 CardHost 能在 Main Process 退出后继续运行；NFR-002 要求卡片位置/锁定状态持续保存。把卡片展示状态的唯一写入权放在 CardHost，能解决离线于主进程期间的保存问题；把文件夹目录等业务主数据留在 Main Process，可避免 CardHost 承担完整业务管理职责。方案 A 还避免了方案 D 的额外进程/服务复杂度。
- 依据：SRS v0.11 FR-016、FR-017、FR-019、NFR-002、NFR-003；ADR-021、ADR-033、ADR-034；P3-03 §6；P3-04 v0.1。
- 依据缺口：尚未选定物理存储后端，跨进程并发写入能力、事务边界和目标 OS 兼容性仍需原型验证；同一用户多会话的状态隔离需进一步检查。
