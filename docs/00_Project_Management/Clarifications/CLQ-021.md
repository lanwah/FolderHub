# CLQ-021：同一文件夹路径重复添加时的处理规则

- 关联问题：Q-023
- 关联需求：RAW-002、RAW-005
- 关联决策：待用户确认；当前无新增 ADR
- 阶段：P2_REQUIREMENT_ANALYSIS
- 状态：OPEN / PENDING_CONFIRMATION
- 记录版本：V1.0
- 创建日期：2026-11-11
- 来源：P2 SRS 数据/异常边界分析发现，已确认“一个文件夹记录可关联多个分类”，但尚未明确同一路径再次添加时是否建立新记录。

## 1. 问题与背景

FolderHub 已确认：
- 一个文件夹记录可以同时关联多个分类。
- 每条文件夹记录最多设置一个可选别名，别名允许重复。
- 文件夹记录保存真实路径。

尚未确认：用户再次拖入或手动添加一个已登记的文件夹路径时，系统应复用已有记录还是创建第二条记录。该规则会影响记录唯一性、分类关联、别名/用途说明维护及数据模型约束。

本问题只讨论“同一实际文件夹路径的重复登记”这一产品行为；路径规范化、符号链接/联接点、大小写和网络路径比较算法留待 P3 技术设计，不在此预先指定。

## 2. 本轮选项

| 选项 | 完整含义 | 优点 | 缺点/代价/风险 |
|---|---|---|---|
| A（推荐） | 同一实际文件夹路径只保留一条 FolderHub 文件夹记录。再次添加时不创建重复记录，而是提示用户将已有记录关联到目标分类；若已关联则提示已存在 | 与“一条记录可属于多个分类”一致；避免同一路径出现多条记录导致别名、用途说明和卡片配置分裂；数据维护较简单 | 同一路径不能在不同分类下维护完全独立的别名/用途说明；需提供“关联到分类”的交互 |
| B | 允许同一路径创建多条独立记录，各自可设置别名、用途说明和分类关系 | 灵活，可在不同分类中用不同描述表达不同用途 | 容易出现重复项；修改路径、卡片和异常状态时可能产生不一致；用户难以判断是否重复 |
| C | 默认阻止重复添加，但允许用户确认后仍创建一条独立记录 | 兼顾避免误重复与特殊场景灵活性 | 增加确认流程和重复记录管理复杂度；需定义何时允许强制创建 |
| D（其他） | 用户自定义重复路径处理规则 | 可满足上述方案之外的具体使用方式 | 需要补充具体规则及其对多分类、别名和卡片配置的影响 |

## 3. 助手推荐

**推荐：A（高置信度）。**

依据：
- 已确认一个文件夹记录可以关联多个分类，因此同一路径跨分类展示已有明确的数据关系机制。
- 已确认单条记录最多一个别名和一个用途说明；若允许重复记录，同一实际目录可能产生多个互相独立的描述和卡片状态，增加维护歧义。
- 选项 A 仅约束产品记录层的重复添加行为；路径比较的技术算法仍留待 P3，不提前冻结技术实现。

可能改变推荐的条件：如果用户明确需要同一物理目录在不同分类中拥有独立别名、用途说明或独立卡片设置，则 B/C 可能更合适。
