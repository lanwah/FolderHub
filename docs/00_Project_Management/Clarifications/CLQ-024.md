# CLQ-024：多显示器、DPI 或分辨率变化后的桌面组件位置恢复

- 关联问题：Q-026
- 关联需求：RAW-011、RAW-013
- 关联决策：ADR-005、ADR-007、ADR-013；本问题待确认，暂不新增 ADR

- 决策处理状态：`CONFIRMED`

## 1. 问题与背景

主组件的位置和锁定状态跨应用重启保存；独立卡片可分别调整位置并锁定。尚未明确当显示器增减、主副屏排列改变、分辨率变化或 DPI 缩放变化时，已保存的位置应如何处理。

本问题只确认用户可见的恢复行为，不决定坐标系、显示器标识、DPI 换算或窗口定位算法；具体实现留待 P3/P4。

## 2. 本轮选项

| 选项 | 完整含义 | 优点 | 缺点/代价/风险 |
|---|---|---|---|
| A（推荐） | 尽量保持组件原先所在显示器及相对位置；若原显示器已不可用，或位置会导致组件完全/部分移出可见桌面，则自动迁移到当前主显示器的可见位置；主组件和每个独立卡片分别恢复 | 最大程度保留用户布局，同时避免组件丢失或不可操作；符合桌面组件持续可访问的预期 | 需要定义“相对位置”和“可见位置”的技术判定，留待设计阶段 |
| B | 只要检测到显示器布局、分辨率或 DPI 变化，就将主组件和所有独立卡片统一移至当前主显示器的默认可见位置 | 规则简单，组件不易丢失 | 用户原有多屏布局会被打乱，多个卡片可能集中重叠 |
| C | 始终保留原保存坐标，不自动迁移；若组件不可见，由用户手动恢复/重置位置 | 不主动改变用户保存的布局 | 组件可能出现在不可见区域，普通用户难以找回；需要额外恢复入口 |
| D（其他） | 用户自定义恢复规则 | 可适应特殊多屏工作方式 | 需补充具体行为与优先级 |

## 3. 助手推荐

**推荐：A（中高置信度）。**

依据：
- 用户已确认桌面组件位置可调整并跨重启保存，位置意外丢失会直接影响核心使用体验。
- 多显示器断开、排列变化和 DPI/分辨率变化都可能使原位置不再可见。
- A 兼顾保留用户布局与避免组件不可访问；技术算法不在 P2 冻结。

未知信息：用户是否希望显示器断开后仍严格保留坐标而不自动迁移。若用户更看重绝对坐标不变，可能改变推荐。
