# CLQ-016：分类是否支持层级/嵌套

- 关联问题：Q-017
- 关联需求：RAW-002
- 阶段：P1_REQUIREMENT_COLLECTION
- 状态：CLOSED / CONFIRMED
- 记录版本：V1.1
- 日期：2026-11-04
- 来源：本轮对 RAW-002 的需求完整性检查；以下选项均为本轮新澄清。

## 1. 问题与背景

已确认分类支持新增、编辑、删除和手动排序，文件夹可同时属于多个分类，删除分类时关联文件夹移至“未分类”。但尚未确认分类之间是否存在父子层级关系。该选择会影响左侧分类导航、分类编辑、排序及删除规则。

## 2. 本轮选项

| 选项 | 完整含义 | 优点 | 缺点/代价/风险 |
|---|---|---|---|
| A | 分类采用平级列表，不支持父子分类或嵌套 | 左侧导航直观；管理和排序简单；与当前“左侧分类、右侧列表”布局一致 | 分类数量很多时，用户需要通过命名或排序组织列表 |
| B | 支持多级父子分类，可展开/折叠子分类 | 适合复杂目录体系，层级关系清晰 | 导航、移动分类、删除父分类及多分类归属规则更复杂 |
| C | 仅支持两级分类（一级分类 + 子分类），不允许更深层级 | 比平级更有组织能力，同时限制复杂度 | 仍需定义父分类删除、子分类排序及文件夹跨层归属行为 |
| D（其他） | 以上均不符合；请自定义分类层级规则 | 可按实际组织习惯定义 | 需要进一步拆分确认 |

## 3. 助手推荐

**推荐：A（高置信度）。** 当前已确认的主界面是左侧分类、右侧文件夹列表，且尚无多级分类的明确业务需求。平级分类足以支持首版分类管理，能减少导航和删除规则复杂度。若实际存在稳定的部门/项目/子目录层级，再考虑 B 或 C。

可能改变推荐的因素：分类预计数量、是否需要按部门/项目形成树状结构，以及用户是否需要拖动分类改变父子关系。
