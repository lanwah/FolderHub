## 2. 项目背景与目标

`AI_DERIVED: AI-DER-000`。以下背景/目标表述是对 RAW-001 及 RAW-002～RAW-013 用户原始需求的结构化综合，不替代原始需求文本。

FolderHub 面向 Windows 本地交互式桌面用户，解决常用文件夹数量较多时，桌面快捷方式难以分类、难以辨认用途、路径不易记忆的问题。

产品通过桌面壁纸层主组件提供分类和文件夹列表，并允许用户将单个文件夹以独立桌面卡片形式显示。用户可以查看分类、识别文件夹用途，并通过交互快速调用 Windows 默认文件资源管理器打开目标路径。

项目目标来自 RAW-001；具体界面形态和行为以 RAW-002～RAW-013 及 ADR-001～ADR-030 为准。

## 3. 产品范围与非目标

### 3.1 首版范围

1. 支持 Windows 10（22H2）和 Windows 11（x64）本地交互式桌面环境。
2. 增加 Windows Server 2012 及以上版本的单用户交互式桌面支持：
   - Windows Server 2012 / 2012 R2：Server with a GUI。
   - Windows Server 2016 及以上：Desktop Experience。
   - 上述为目标支持范围，兼容性仍需逐版本验证。
3. 提供桌面壁纸层主组件，界面采用左侧分类、右侧文件夹列表。
4. 提供分类和文件夹记录管理、别名、用途说明、路径维护、名称/别名搜索、文件夹打开。
5. 提供托盘常驻、可配置开机启动、主组件显示/位置调整/锁定和透明度配置。
6. 支持单个文件夹独立桌面卡片；多个卡片可同时存在，并独立调整位置和锁定。
7. 支持配置退出主程序后独立卡片是否保留；该设置全局统一，默认开启。

## 4. 用户角色与使用场景

### 4.1 用户角色

| 角色 | 描述 | 确认状态 |

本项目当前未确认管理员角色、远程多用户角色或跨用户共享配置需求；不得自行扩展。

### 4.2 主要使用场景

> `AI_DERIVED: AI-DER-002`。以下场景是对已确认启动/托盘、分类/文件夹管理、搜索、独立卡片及退出规则的流程化归纳，不新增用户未确认行为；适用范围限于 SRS 草案，须在 P2 评审中检查追踪关系。

1. 用户启动 Windows 后，FolderHub 按配置决定是否自动启动；默认运行方式为托盘常驻，主组件默认隐藏。
2. 用户从系统托盘打开主界面，在左侧选择分类，右侧查看该分类关联的文件夹。
3. 用户创建/编辑分类和文件夹记录，设置别名、用途说明及真实路径。
4. 用户将资源管理器中的文件夹拖拽至 FolderHub，建立文件夹记录。
5. 用户通过名称或别名搜索目标文件夹，双击或通过右键菜单打开文件夹。
6. 用户将某个文件夹单独固定为桌面卡片；卡片可独立移动和锁定，不依赖主组件显示。
7. 用户退出主程序时，根据全局设置决定独立卡片是否继续显示。

## 5. 业务流程与业务规则

### 5.1 分类与文件夹关系

- 分类采用平级列表，不支持嵌套。
- 一个文件夹记录可以同时关联多个分类。
- 同一实际文件夹路径只保留一条 FolderHub 记录；再次添加时复用已有记录并提示关联到目标分类；若已关联则提示已存在，不创建重复记录（ADR-028）。
- 分类和文件夹均支持新增、编辑、删除及手动排序。
- 每个分类独立维护其文件夹排序；同一文件夹在不同分类中可以有不同位置。
- 删除分类时，该分类关联的文件夹记录移至“未分类”。
- 删除文件夹记录只移除 FolderHub 登记，不删除磁盘上的真实目录。

### 5.2 文件夹信息规则

- 每条文件夹记录最多设置一个可选别名；别名允许重复。
- 列表优先显示别名；未设置别名时显示真实文件夹名称。
- 搜索匹配别名和真实文件夹名称。
- 搜索采用不区分大小写的包含匹配；输入变化时动态更新；清空关键词恢复当前分类完整列表；无匹配结果时显示明确提示（ADR-029）。
- 用途说明为可选字段；主组件列表和独立卡片均显示。
- 长用途说明在列表/卡片中截断；用户可通过详情或悬停查看完整内容，不设严格字数限制。

### 5.3 路径与打开规则

- 文件夹记录保存真实路径。
- 路径不可用时保留记录并标记异常，允许用户重新指定路径。
- 不自动删除路径异常记录或磁盘目录。
- 主要在用户尝试打开时检查路径；路径恢复可访问后允许再次打开。
- 主组件列表和独立卡片均支持双击打开；单击仅选中；右键菜单提供“打开文件夹”。
- 打开动作调用 Windows 默认文件资源管理器；路径不可用时提示用户。

### 5.4 桌面组件规则

- 主组件显示层级为桌面壁纸层。
- 主组件布局为左侧分类、右侧文件夹列表。
- 主组件可配置是否固定到桌面；未锁定时可移动/调整，锁定后禁止移动/调整。
- 主组件位置和锁定状态跨应用重启保存。
- 主组件透明度范围为 20%～100%，默认 88%；仅背景透明，文字和图标保持不透明；滑块实时预览并自动保存。
- 每个文件夹可单独启用独立桌面卡片，默认关闭；卡片显示图标、名称和用途说明。
- 独立卡片不依赖主组件显示；多个卡片可同时存在；每个卡片可独立调整位置并锁定。
- 退出主程序后独立卡片保留设置为全局统一开关，不提供逐卡片覆盖，默认开启。开启时继续显示，关闭时全部关闭。
- 独立卡片的进程/服务生命周期技术实现留待 P3（Q-015）。

## 8. 界面与交互要求

### 8.1 主组件

- 显示层级：桌面壁纸层。
- 主布局：左侧分类、右侧文件夹列表。
- 启动后默认隐藏主组件，托盘常驻；从托盘菜单打开主界面。
- 主组件支持固定显示、位置调整、锁定及背景透明度设置。
- 文件夹列表显示优先别名、用途说明；用途说明较长时截断并提供完整内容查看方式。

### 8.2 独立文件夹卡片

- 每张卡片对应一个文件夹记录。
- 展示图标、名称和用途说明。
- 卡片与主组件显示状态相互独立。
- 多张卡片可以同时显示，每张卡片独立移动和锁定。
- 退出后是否保留由全局设置控制。

### 8.3 已知交互细节缺口

以下细节尚未由用户明确确认，暂不固化为需求：

## 11. 外部依赖与约束

1. 依赖 Windows 桌面交互环境、系统托盘和 Windows 默认文件资源管理器。
2. 文件夹路径是否可访问取决于本机文件系统、网络位置、可移动介质和当前用户权限；FolderHub 不应将路径不可用等同于记录应删除。
3. Windows Server 目标环境兼容性属于 RISK-001，需在 P3/P4 建立逐版本测试矩阵。
4. 同类项目调研按 ADR-016 执行，调研结果为技术路线建议，不构成技术选型批准。
5. 同一路径记录唯一性为已确认产品规则；路径规范化、符号链接/联接点、大小写和网络路径等路径等价判定算法留待 P3 技术设计。
5. 技术栈、Win32 API 使用方式、数据库、配置格式、开机启动实现方式及桌面组件实现机制均未批准，留待 P3。

## 18. Q-029～Q-150 已确认需求补充（P2 草案）

> 本节把历史对话中已确认的产品规则纳入 SRS 草案。逐题结论依据历史摘要重建（RECONSTRUCTED）；不代表完整恢复原始提问、选项和用户逐字回答。所有条目仍为 P2 DRAFT，待整体评审；不构成需求基线。

### Q-029 / CLQ-025：独立卡片尺寸

小、中、大三种预设尺寸；每张卡片可单独选择；系统默认尺寸可配置，新建卡片采用默认值；单张修改不影响其他卡片或默认值。

### Q-030 / CLQ-026：独立卡片位置冲突

自动检测卡片位置冲突；拖动时尽量避免重叠；冲突时自动调整到附近可用位置，尽量保留用户布局意图；具体算法留待设计。

### Q-031 / CLQ-027：备份文件格式

备份为单个 ZIP 文件，扩展名 .zip；常见压缩工具可查看；恢复由 FolderHub 解析并校验。

### Q-032 / CLQ-028：备份目录设置

首次备份弹出目录选择；记住上次备份目录；后续默认使用；设置中可修改；原目录不可用时提示并允许重新选择。

### Q-033 / CLQ-029：备份完整性校验

备份完成后自动检查完整性；恢复前再次检查；损坏时提示并禁止直接恢复；完整性校验不等于加密或安全认证。

### Q-034 / CLQ-030：备份密码保护

支持可选密码加密；加密备份恢复需正确密码；未加密备份仍可恢复；忘记密码不能绕过解密。

### Q-035 / CLQ-031：备份恢复模式

完全覆盖恢复；恢复前提示并要求明确确认；不合并；不删除或修改目标文件夹真实文件内容。

### Q-036 / CLQ-032：恢复前安全备份

覆盖恢复前自动备份当前 FolderHub 管理数据和设置；临时备份成功才允许恢复；失败禁止继续；恢复失败保留当前数据和临时备份；临时备份位置/保留期限/清理机制留待设计。

### Q-037 / CLQ-033：备份版本兼容

新版本尽量支持恢复旧版本备份；旧版本不保证支持新版本备份；备份包含格式版本信息；不兼容时明确提示并禁止强行恢复；迁移规则留待设计。

### Q-038 / CLQ-034：恢复失败回滚

恢复过程中保护恢复前数据；失败自动回滚；回滚成功恢复原有数据和设置；回滚失败保留恢复前临时备份；明确提示恢复失败和回滚结果；事务/断电恢复留待设计。

### Q-039 / CLQ-035：自动备份范围

首版仅手动备份，不提供定期自动备份；恢复前自动临时备份仍保留。

### Q-040 / CLQ-036：备份命名与历史

批量重试后自动刷新；成功记录移除，失败记录保留待清理状态；保留搜索/筛选；当前页空则回第一页；显示摘要。

### Q-121 / CLQ-117：批量重试状态持久化

批量重试逐条保存执行状态；意外退出后，已成功清理不重复处理；尚未执行或结果不确定的记录，重启后检查实际状态；未完成继续处理；不影响其他备份/恢复历史。

### Q-122 / CLQ-118：重启后自动续行反馈

重启后自动继续未完成任务，处理期间不逐条弹窗；完成后汇总恢复处理数量、成功、失败；全部成功提示完成；失败提示原因和备份管理入口。

### Q-123 / CLQ-119：批量重试进度显示

批量重试显示总体进度（例如 8/20）、进度条、当前处理记录名称；结束后显示成功数量、失败数量及原因。

### Q-124 / CLQ-120：批量重试取消

批量重试期间允许取消；当前单条完成后停止；已成功不恢复；未执行保持待清理；显示完成/取消/剩余数量。

### Q-125 / CLQ-121：批量重试取消确认

取消批量重试前二次确认，显示已完成和剩余数量；确认后才取消；继续则返回原进度。

### Q-126 / CLQ-122：批量重试取消结果摘要

取消后显示完整结果摘要：总数、成功、失败、未执行、失败名称和原因；标记用户取消；未执行仍待清理；不保存独立批量操作历史。

### Q-127 / CLQ-123：批量重试摘要复制

支持复制完整结果摘要为普通文本，不生成文件。

### Q-128 / CLQ-124：批量重试摘要关闭后行为

摘要关闭后不保留独立摘要或再次查看入口；状态仍在备份管理列表体现。

### Q-129 / CLQ-125：批量重试摘要时间

摘要显示开始和完成/取消时间；使用本地时间格式 YYYY-MM-DD HH:mm:ss；不显示耗时。

### Q-130 / CLQ-126：待清理记录状态与详情

备份管理列表显示待清理状态和失败标识；详情显示最近一次失败原因；支持详情直接重试；不保存独立批量操作历史。

### Q-131 / CLQ-127：待清理成功后的记录清理

清理成功后管理记录移除，失败信息一并清除；不保留失败历史。

### Q-132 / CLQ-128：待清理详情重试时间

详情显示最近一次重试时间；每次重试失败更新；成功后随管理记录清理；不留重试历史。

### Q-133 / CLQ-129：待清理累计重试次数

详情显示累计重试次数；每次实际发起重试时递增；自动/手动都计入；成功后随管理记录清理。

### Q-134 / CLQ-130：自动重试次数上限

每条记录累计自动重试最多 3 次；达到 3 次后停止自动重试，但手动重试不限；单独保存自动重试次数。

### Q-135 / CLQ-131：自动重试上限展示

达到自动重试上限后列表显示“自动重试已达上限”；详情显示自动重试 3 次、最近失败原因/时间；保留手动重试入口。

### Q-136 / CLQ-132：手动失败后重置自动重试机会

自动重试达到上限后，用户手动重试若失败，自动重试次数重置为 0，重新开放最多 3 次自动重试机会；累计重试总次数不重置；手动成功则清理记录。

### Q-137 / CLQ-133：自动重试周期

自动重试周期数不限制；每周期最多自动重试 3 次；手动重试失败后开启新周期；每周期独立计数，累计总次数持续增加。

### Q-138 / CLQ-134：自动重试间隔

每条记录两次自动重试至少间隔 1 小时；不足 1 小时启动时跳过；手动重试不受间隔限制。

### Q-139 / CLQ-135：自动重试间隔计算起点

1 小时间隔从上次自动重试开始时间计算，不论上次成功/失败；手动重试不受间隔。

### Q-140 / CLQ-136：启动时多条记录自动重试顺序

启动时多条记录自动重试逐条串行；一条完成再处理下一条；失败不影响其他记录；支持状态持久化和异常恢复。

### Q-141 / CLQ-137：自动重试后台运行方式

自动重试后台执行、不阻塞主界面；托盘状态或提示区域显示正在处理；不弹独立进度窗口；结束后汇总成功/失败数量；失败记录留在备份管理列表。

### Q-142 / CLQ-138：启动自动重试全局开关

提供全局设置开关“启动时自动重试待清理记录”，默认开启；关闭后停止自动重试，手动不受影响；重新开启后下次启动继续。

### Q-143 / CLQ-139：运行中关闭自动重试

运行中关闭开关，当前单条完成后停止后续自动重试；已完成保持结果；未处理保持待清理；重新开启后下次启动再继续。

### Q-144 / CLQ-140：运行中重新开启自动重试

当前运行中重新开启开关，不立即恢复；下次启动再恢复；重新检查符合条件记录，遵守周期和 1 小时规则。

### Q-145 / CLQ-141：启动自动重试延迟

FolderHub 基本初始化完成后延迟 30 秒再检查/执行自动重试；后台运行，不阻塞主界面/托盘。

### Q-146 / CLQ-142：延迟期间退出

30 秒延迟期间退出，取消本次自动重试；不增加自动重试次数，不更新上次自动重试开始时间；下次启动重新延迟并检查。

### Q-147 / CLQ-143：自动重试执行中正常退出

自动重试执行中退出，当前单条完成后退出，不启动下一条；保存状态；未处理记录待清理；下次启动依既定规则恢复。

### Q-148 / CLQ-144：Windows 意外关机/重启恢复

Windows 意外关机/重启后，下次启动检查实际状态并恢复；执行状态持久化；不直接认定成功/失败；已完成不重复；未完成/不确定重新检查后继续；不重复消耗已确认次数。

### Q-149 / CLQ-145：中断后按实际状态判断

中断后按 ZIP 文件和管理记录实际状态判断：ZIP 不存在、记录存在→继续清理管理记录；两者均不存在→完成；ZIP 存在、记录存在→重新执行清理流程；检查异常/无法确认→保留并提示，不盲目删除。

### Q-150 / CLQ-146：中断任务恢复优先级

重启后优先检查并恢复上次中断任务；已完成不重复；未完成按 Q-149 判断；上次任务处理完成后再处理其他符合条件记录；串行执行，不改变其他记录的自动重试次数/周期。
