## 2. 项目背景与目标

FolderHub 面向 Windows 本地交互式桌面用户，解决常用文件夹数量较多时，桌面快捷方式难以分类、难以辨认用途、路径不易记忆的问题。

产品通过桌面壁纸层主组件提供分类和文件夹列表，并允许用户将单个文件夹以独立桌面卡片形式显示。用户可以查看分类、识别文件夹用途，并通过交互快速调用 Windows 默认文件资源管理器打开目标路径。

项目目标来自 RAW-001；具体界面形态和行为以 RAW-002～RAW-013 及 ADR-001～ADR-027 为准。

## 3. 产品范围与非目标

### 3.1 首版范围

1. 支持 Windows 10（22H2）和 Windows 11（x64）本地交互式桌面环境。
2. 增加 Windows Server 2012 及以上版本的单用户交互式桌面支持：
   - Windows Server 2012 / 2012 R2：Server with a GUI。
   - Windows Server 2016 及以上：Desktop Experience。
   - 上述为目标支持范围，兼容性仍需逐版本验证。
3. 提供桌面壁纸层主组件，界面采用左侧分类、右侧文件夹列表。
4. 提供分类和文件夹记录管理、别名、用途说明、路径维护、名称/别名搜索、文件夹打开。
5. 提供托盘常驻、可配置开机启动、主组件显示/位置调整/锁定和透明度配置。
6. 支持单个文件夹独立桌面卡片；多个卡片可同时存在，并独立调整位置和锁定。
7. 支持配置退出主程序后独立卡片是否保留；该设置全局统一，默认开启。

## 4. 用户角色与使用场景

### 4.1 用户角色

| 角色 | 描述 | 确认状态 |
|---|---|---|
| 本机交互式桌面用户 | 在受支持的 Windows 桌面会话中启动、配置和使用 FolderHub 的用户 | 由首版运行环境范围归纳；具体账户权限模型未定义 |

本项目当前未确认管理员角色、远程多用户角色或跨用户共享配置需求；不得自行扩展。

### 4.2 主要使用场景

1. 用户启动 Windows 后，FolderHub 按配置决定是否自动启动；默认运行方式为托盘常驻，主组件默认隐藏。
2. 用户从系统托盘打开主界面，在左侧选择分类，右侧查看该分类关联的文件夹。
3. 用户创建/编辑分类和文件夹记录，设置别名、用途说明及真实路径。
4. 用户将资源管理器中的文件夹拖拽至 FolderHub，建立文件夹记录。
5. 用户通过名称或别名搜索目标文件夹，双击或通过右键菜单打开文件夹。
6. 用户将某个文件夹单独固定为桌面卡片；卡片可独立移动和锁定，不依赖主组件显示。
7. 用户退出主程序时，根据全局设置决定独立卡片是否继续显示。

## 5. 业务流程与业务规则

### 5.1 分类与文件夹关系

- 分类采用平级列表，不支持嵌套。
- 一个文件夹记录可以同时关联多个分类。
- 同一实际文件夹路径只保留一条 FolderHub 记录；再次添加时复用已有记录并提示关联到目标分类；若已关联则提示已存在，不创建重复记录（ADR-028）。
- 分类和文件夹均支持新增、编辑、删除及手动排序。
- 每个分类独立维护其文件夹排序；同一文件夹在不同分类中可以有不同位置。
- 删除分类时，该分类关联的文件夹记录移至“未分类”。
- 删除文件夹记录只移除 FolderHub 登记，不删除磁盘上的真实目录。

### 5.2 文件夹信息规则

- 每条文件夹记录最多设置一个可选别名；别名允许重复。
- 列表优先显示别名；未设置别名时显示真实文件夹名称。
- 搜索匹配别名和真实文件夹名称。
- 用途说明为可选字段；主组件列表和独立卡片均显示。
- 长用途说明在列表/卡片中截断；用户可通过详情或悬停查看完整内容，不设严格字数限制。

### 5.3 路径与打开规则

- 文件夹记录保存真实路径。
- 路径不可用时保留记录并标记异常，允许用户重新指定路径。
- 不自动删除路径异常记录或磁盘目录。
- 主要在用户尝试打开时检查路径；路径恢复可访问后允许再次打开。
- 主组件列表和独立卡片均支持双击打开；单击仅选中；右键菜单提供“打开文件夹”。
- 打开动作调用 Windows 默认文件资源管理器；路径不可用时提示用户。

### 5.4 桌面组件规则

- 主组件显示层级为桌面壁纸层。
- 主组件布局为左侧分类、右侧文件夹列表。
- 主组件可配置是否固定到桌面；未锁定时可移动/调整，锁定后禁止移动/调整。
- 主组件位置和锁定状态跨应用重启保存。
- 主组件透明度范围为 20%～100%，默认 88%；仅背景透明，文字和图标保持不透明；滑块实时预览并自动保存。
- 每个文件夹可单独启用独立桌面卡片，默认关闭；卡片显示图标、名称和用途说明。
- 独立卡片不依赖主组件显示；多个卡片可同时存在；每个卡片可独立调整位置并锁定。
- 退出主程序后独立卡片保留设置为全局统一开关，不提供逐卡片覆盖，默认开启。开启时继续显示，关闭时全部关闭。
- 独立卡片的进程/服务生命周期技术实现留待 P3（Q-015）。

## 8. 界面与交互要求

### 8.1 主组件

- 显示层级：桌面壁纸层。
- 主布局：左侧分类、右侧文件夹列表。
- 启动后默认隐藏主组件，托盘常驻；从托盘菜单打开主界面。
- 主组件支持固定显示、位置调整、锁定及背景透明度设置。
- 文件夹列表显示优先别名、用途说明；用途说明较长时截断并提供完整内容查看方式。

### 8.2 独立文件夹卡片

- 每张卡片对应一个文件夹记录。
- 展示图标、名称和用途说明。
- 卡片与主组件显示状态相互独立。
- 多张卡片可以同时显示，每张卡片独立移动和锁定。
- 退出后是否保留由全局设置控制。

### 8.3 已知交互细节缺口

以下细节尚未由用户明确确认，暂不固化为需求：
- 搜索框位置、触发方式、大小写/部分匹配规则和无结果提示（Q-024 / CLQ-022）。
- 卡片图标来源、卡片尺寸、显示重叠处理。
- 多显示器、DPI 缩放、分辨率变化时的位置恢复规则。

## 10. 异常、边界与恢复场景

| 场景 | 期望行为 | 来源/状态 |
|---|---|---|
| 文件夹路径不存在或不可访问 | 保留记录，标记异常；用户可重新指定路径 | ADR-019 / 已确认 |
| 网络/可移动存储路径暂时断开后恢复 | 不删除记录；恢复后允许再次访问 | ADR-019 / 已确认 |
| 删除分类 | 关联文件夹记录转入“未分类” | ADR-010 / 已确认 |
| 删除文件夹记录 | 仅移除 FolderHub 登记，不删除真实目录 | ADR-010 / 已确认 |
| 再次添加已登记路径 | 复用已有记录；按需建立分类关联；若目标分类已关联则提示已存在，不创建重复记录 | ADR-028 / 已确认 |
| 主程序退出且全局保留开关开启 | 独立卡片继续显示 | ADR-021 / 已确认 |
| 主程序退出且全局保留开关关闭 | 所有独立卡片关闭 | ADR-021 / 已确认 |
| 独立卡片宿主进程异常退出、崩溃恢复 | 行为尚未定义，需在后续澄清/设计阶段处理 | 待分析；不擅自假设 |
| 显示器布局或 DPI 改变导致坐标失效 | 恢复策略尚未定义 | 待分析；不擅自假设 |

## 11. 外部依赖与约束

1. 依赖 Windows 桌面交互环境、系统托盘和 Windows 默认文件资源管理器。
2. 文件夹路径是否可访问取决于本机文件系统、网络位置、可移动介质和当前用户权限；FolderHub 不应将路径不可用等同于记录应删除。
3. Windows Server 目标环境兼容性属于 RISK-001，需在 P3/P4 建立逐版本测试矩阵。
4. 同类项目调研按 ADR-016 执行，调研结果为技术路线建议，不构成技术选型批准。
5. 同一路径记录唯一性为已确认产品规则；路径规范化、符号链接/联接点、大小写和网络路径等路径等价判定算法留待 P3 技术设计。
5. 技术栈、Win32 API 使用方式、数据库、配置格式、开机启动实现方式及桌面组件实现机制均未批准，留待 P3。

## 12. 验收标准汇总

P2 需求验收以第 6～11 章中的可观察标准为基础。进入开发/测试阶段后，应将需求验收标准拆分为具体测试用例，并维持 RAW → FR/BR/UIR/NFR → 设计模块 → 测试项的双向追踪。

当前可确认的验收边界：
- 分类、文件夹记录、多分类关系和分类内排序可按已确认规则验证。
- 别名、用途说明、拖拽添加、路径异常恢复和打开交互可按已确认规则验证。
- 托盘、开机启动、主组件桌面固定/锁定/透明度及独立卡片行为可按已确认规则验证。
- 平台兼容性需逐版本测试，当前不得标记为通过。
- 尚未确认的默认值和边界行为不得擅自写入测试预期。
