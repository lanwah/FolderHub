## 1. 目的与范围

本工作包用于检查 REQ-BL-1.0 的正式需求是否能沿着“需求 → 逻辑模块 → 接口边界 → 验证工作”追踪，并识别当前 P3 设计草案的覆盖缺口、质量属性约束和未验证事项。

范围包括：
- FR-001～FR-019（19 项）；
- BR-001～BR-012（12 项）；
- UIR-001～UIR-002（2 项）；
- NFR-001～NFR-004（4 项）；
- P3-01～P3-07 已形成的逻辑架构、数据、IPC、安全及生命周期分析；并吸收 ADR-039/040 的后端与显示位置策略确认。

不包括：修改需求语义、增加新的质量指标数值、选定数据库/序列化库/运行时/UI 框架/Win32 API/物理存储布局，或宣称 PoC/实机测试已经通过。

## 3. 逻辑模块目录（候选）

| 模块 ID | 逻辑模块 | 主要职责 | 边界约束 | 依据/状态 |
|---|---|---|---|---|
| M-01 | Domain / 领域模型 | Category、FolderRecord、CategoryFolderLink、CardDefinition、全局设置等业务实体与规则；路径唯一性抽象 | 不依赖 UI、HWND、Named Pipes 或具体数据库 | P3-02/P3-04；逻辑候选 |
| M-02 | Application / 用例编排 | 分类/文件夹 CRUD、排序、搜索、卡片启停、退出策略、打开文件夹等用例 | 不直接调用 Win32、注册表或数据库 | P3-02；逻辑候选 |
| M-03 | Main UI | 主组件、分类导航、文件夹列表、搜索、编辑与设置界面 | UI 不持有 CardHost 的独立进程生命周期 | P3-02；Demo v0.1 仅交互参照 |
| M-04 | Tray & Startup Adapter | 托盘图标/菜单、开机启动设置和命令入口 | 不承载业务规则或卡片窗口绘制 | P3-02；系统集成待验证 |
| M-05 | Shell / Folder Adapter | 资源管理器拖拽入口、路径访问检查、默认文件资源管理器打开 | 路径失效不得自动删除 FolderRecord 或真实目录 | P3-01/P3-02；API 待验证 |
| M-06 | Windows Desktop Adapter | 桌面壁纸层、窗口样式/层级、透明背景、移动/锁定等平台适配 | 平台句柄/API 不泄漏到领域层 | P3-01/P3-02；NEEDS_VALIDATION |
| M-07 | Display & Position Adapter | 显示器识别、工作区、DPI/坐标转换、可见性判断和迁移 | 主组件与每张卡片分别判断；算法/字段尚未选定 | P3-01/P3-04；NEEDS_VALIDATION |
| M-08 | Persistence Adapter | Repository/Store 抽象、版本化迁移、备份/完整性边界 | 逻辑写入权遵守 ADR-035；物理后端未定 | P3-04；NEEDS_VALIDATION |
| M-09 | CardHost Runtime & Card UI | 当前会话全部独立卡片窗口的创建、显示、交互、关闭和生命周期 | 每会话一个 CardHost；不承担主界面完整业务 UI | ADR-034/037、P3-03/P3-06；逻辑候选 |
| M-10 | IPC Contract / Named Pipes Adapter | Main Process 与 CardHost 握手、消息、同步、错误、超时、重连 | 使用 Named Pipes；身份/消息安全按 ADR-036、P3-07；遵守 ADR-035 写入权 | P3-05/P3-07；安全 PoC 未验证 |
| M-11 | Diagnostics & Recovery Coordinator | 结构化诊断、失败分类、恢复对账、重试/退避和状态报告 | 不静默吞错、不把未知结果当成功；不擅自新增 Supervisor | P3-05/P3-06；实现细节待验证 |
| M-12 | Deployment & Compatibility Boundary | 安装/升级/回退、进程版本协调、目标 OS 兼容性矩阵 | 不缩减已批准目标 OS 范围；不将支持目标误报为已验证 | P3-02/P3-03；NEEDS_VALIDATION |

> M-01～M-12 是逻辑模块候选。是否拆成独立程序集、类库、进程或部署包，须由后续设计证据决定；不得将本表视为技术架构批准。

## 4. 接口边界目录（逻辑契约）

| 接口 ID | 提供方 → 使用方 | 主要交互 | 关键约束 | 当前状态 |
|---|---|---|---|---|
| IF-01 | Main UI → Application | 用户操作/查询/展示模型 | UI 不直接写存储或操作系统句柄 | 逻辑候选 |
| IF-02 | Application ↔ Domain | 用例执行、规则校验、领域结果 | 业务规则单一实现；错误结果显式 | 逻辑候选 |
| IF-03 | Application ↔ Persistence | 读取/提交业务数据与配置 | Main Process 写入其权威聚合；版本/迁移待设计 | 逻辑候选 |
| IF-04 | Main Process ↔ CardHost | Named Pipes 请求/响应/事件 | DACL、User SID + Logon SID、拒绝远程、身份握手、帧长/类型/载荷校验；幂等和版本检查 | 传输已选；实现 NEEDS_VALIDATION |
| IF-05 | CardHost ↔ CardPresentation Store | 卡片位置/锁定/显示环境状态读写 | CardHost 为唯一逻辑写入者；提交后才确认成功 | 逻辑候选；持久化 PoC 待验证 |
| IF-06 | Main Process ↔ CardDefinition/GlobalSettings Store | 业务定义和全局策略读写 | Main Process 为唯一逻辑写入者 | 逻辑候选；物理后端未定 |
| IF-07 | Main/CardHost → Windows Desktop Adapter | 窗口显示、位置、层级、透明度 | API/窗口层级行为必须目标 OS 实测 | NEEDS_VALIDATION |
| IF-08 | Main/CardHost → Display & Position Adapter | 显示器/DPI 环境采集和位置恢复 | 按 FR-019 对主组件/每张卡片独立处理 | NEEDS_VALIDATION |
| IF-09 | Application → Shell / Folder Adapter | 拖拽接收、路径检查、打开目录 | 删除登记与真实目录操作严格分离 | 逻辑候选；平台测试待执行 |
| IF-10 | Main Process → Tray & Startup Adapter | 托盘菜单和登录启动配置 | 遵守 ADR-003/004/012/021 | NEEDS_VALIDATION |
| IF-11 | All runtime modules → Diagnostics | 结构化事件、错误码、关联 ID | 日志最小化/脱敏；不记录不必要完整路径/令牌 | 设计约束；实现待验证 |
| IF-12 | Main Process ↔ CardHost Recovery/Reconcile | 版本对账、未知结果查询、幂等恢复 | CardDefinition 与 CardPresentationState 不交叉覆盖；按 ADR-035/037 | 逻辑候选；故障注入待验证 |

> 接口未定义最终方法签名、序列化格式、帧结构或具体错误码；这些属于后续详细设计。IF-04 已有 Named Pipes 传输层用户选择，但不代表消息协议或安全实现已完成。
