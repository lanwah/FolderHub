# FolderHub P3 概要设计工作计划

- 文档编号：FH-HLD-PLAN-001
- 版本：v0.1
- 日期：2026-11-20
- 工作流规范：software-predev-workflow-skill V2.6.1
- 阶段：P3_HIGH_LEVEL_DESIGN
- 状态：IN_PROGRESS / WORK PLAN（非设计基线）
- 需求输入基线：REQ-BL-1.0（SRS_FolderHub_v0.11.md）

## 1. 目标与范围

基于已批准需求基线 REQ-BL-1.0 形成 FolderHub 概要设计，覆盖系统上下文、架构候选与权衡、技术选型依据、模块边界与依赖、关键业务流程、数据模型、外部接口、质量属性、部署配置、技术风险验证计划及需求—模块追踪矩阵。

本计划只建立 P3 工作范围和任务入口，不预先决定技术栈、数据库、Win32 API 方案或独立卡片宿主机制。

## 2. 首批工作

| 工作编号 | 内容 | 关联 | 完成条件 |
|---|---|---|---|
| P3-01 | 系统上下文、外部参与者、运行边界与总体约束 | REQ-BL-1.0 | 形成可评审上下文视图及边界说明 |
| P3-02 | 架构候选方案与权衡 | REQ-BL-1.0；ADR-016 | 对候选方案说明约束、优缺点、成本、风险和验证依据；未验证项标记 NEEDS_VALIDATION |

## 3. 后续设计工作包

- 模块划分、职责、依赖与组件关系。
- 核心业务流程及状态边界。
- 核心数据模型、持久化、迁移、备份与恢复。
- 外部接口及 Windows 系统集成。
- 安全、性能、可靠性、兼容性与可观测性。
- 部署、启动、升级、配置及故障处理。
- 逐版本 Windows Server 兼容性验证矩阵（关联 RISK-001）。
- RAW/SRS 需求到模块的双向追踪矩阵。

## 4. 关键约束与门禁

1. 所有设计均以 REQ-BL-1.0 为输入，不得静默修改已批准需求。
2. 任何需求语义变化先走 CR；技术方案涉及实质性用户选择时按 V2.6.1 建立 Q/CLQ/ADR。
3. Q-015 在独立卡片宿主/生命周期架构批准和相关设计基线前必须完成分析及必要确认。
4. RISK-001 保持 ACCEPTED，但不能将其解释为 Windows Server 兼容性已验证。
5. 未经用户明确批准 P3 概要设计，不得进入 P4。
6. 本计划、草案和建议不构成概要设计基线；HLD 基线须在 P3 评审批准后单独建立。
