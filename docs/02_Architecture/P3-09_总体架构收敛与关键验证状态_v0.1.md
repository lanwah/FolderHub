## 3. 总体逻辑架构

### 3.1 逻辑组件

| 逻辑组件                            | 主要职责                                                                          | 权威边界/限制                             |
|:------------------------------------|:----------------------------------------------------------------------------------|:------------------------------------------|
| Main UI / Application               | 主界面、托盘、设置、分类/文件夹用例、卡片定义管理                                 | 不长期承载独立卡片窗口                    |
| Domain                              | 分类、文件夹、路径唯一性、卡片业务规则                                            | 不依赖 HWND、Named Pipes 或具体存储技术   |
| Main Data Access                    | Category、FolderRecord、CategoryFolderLink、GlobalSettings、CardDefinition 的读写 | Main Process 唯一逻辑写入者；物理后端未定 |
| CardHost Runtime                    | 当前会话卡片窗口创建、显示、交互、关闭与独立运行                                  | 每交互式用户会话一个实例                  |
| Card Presentation State             | 卡片位置、锁定和展示状态读写                                                      | CardHost 唯一逻辑写入者；物理后端未定     |
| IPC Contract / Named Pipes Adapter  | 握手、命令、响应、事件、版本校验、重连和错误分类                                  | 使用 Named Pipes；安全实现未验证          |
| Windows Desktop Adapter             | 桌面层级、窗口样式、透明度、显示器/DPI、Shell、托盘与启动适配                     | 平台 API 与领域逻辑隔离                   |
| Diagnostics & Recovery Coordinator  | 错误分类、关联 ID、恢复对账、重试/退避和诊断                                      | 不静默吞错；不把未知结果当成功            |
| Deployment & Compatibility Boundary | 安装、升级、回退、进程版本协调和 OS 矩阵                                          | 不缩减已批准目标 OS                       |

逻辑模块不等于已确定程序集、类库、物理部署或具体 API。

### 3.2 IPC 端点方向

CardHost 持有 Named Pipe Server、Main Process 作为
Client，是当前设计候选而非已确认决策。其理由是 CardHost 必须在 Main
Process 退出后继续运行；但端点创建、发现、实例防抢占和身份握手均未通过
PoC。不得把该方向写成已验证结论。

### 3.3 部署边界

- Main Process 与当前交互式用户会话 CardHost 均运行于用户交互式会话。
- Windows Service / Session 0 不直接承载用户可见卡片窗口。
- 不新增脱离 Main Process 的常驻 Supervisor。
- 具体进程启动、Job Object、单实例互斥、升级/回滚策略仍需详细设计。

## 4. 数据权威与一致性

1.  Main Process 负责
    Category、FolderRecord、CategoryFolderLink、GlobalSettings 和
    CardDefinition。
2.  CardHost 负责该会话 CardPresentationState。
3.  对方可读取必要摘要，但不得越权写入对方拥有的聚合。
4.  Main Process 重启后不得以旧展示状态快照覆盖 CardHost
    已成功提交的新状态。
5.  删除文件夹登记与关闭关联卡片是跨聚合操作；CardHost
    不可达或处理失败时必须保留可恢复/可对账状态，不得静默删除业务记录。
6.  任何删除登记操作不得删除磁盘上的真实文件夹目录。

物理存储后端、单库/分库、事务/原子提交、迁移、备份和损坏恢复均未选定。

## 5. IPC 安全与协议约束

- 显式最小权限 DACL；不得依赖默认宽松 ACL。
- 校验 User SID、Logon SID、SessionId；拒绝非目标会话和远程客户端。
- 不得仅凭管道名称、PID 或消息 senderRole 信任对端。
- 连接握手应绑定预期进程身份、hostInstanceId、protocol version 和
  challenge/nonce。
- 消息采用类型白名单、长度/字段约束、版本校验和幂等标识。
- 写命令应绑定 messageId、correlationId、aggregateId、expectedVersion。
- 对结果未知的命令通过查询/对账恢复，不盲目重放非幂等副作用。
- 日志最小化并脱敏，不记录认证秘密或不必要的完整路径。

以上是设计约束；NP-01～NP-11 全部未执行，不代表安全实现通过。
